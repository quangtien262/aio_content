Git Worktree: Làm việc với nhiều nhánh cùng lúc mà không cần chuyển qua lại

Bạn đang phát triển một tính năng dở dang thì phải xử lý hotfix khẩn cấp. Cách quen thuộc là commit tạm, dùng git stash hoặc clone thêm repository. Git Worktree cung cấp một lựa chọn gọn hơn: mở nhiều working tree gắn với cùng một repository.

Mỗi worktree là một thư mục làm việc độc lập, có thể checkout một branch riêng. Các worktree dùng chung lịch sử Git và object database nên nhẹ hơn việc clone toàn bộ repository nhiều lần.

Git Worktree là gì?

Một repository Git có một main worktree được tạo khi clone hoặc init. Lệnh git worktree add tạo thêm linked worktree cùng metadata để Git phân biệt từng thư mục.

Ví dụ, project chính đang ở branch feature/checkout. Bạn có thể tạo thư mục khác checkout branch hotfix/payment, mở cả hai trong hai cửa sổ IDE và làm việc song song.

Kiểm tra các worktree hiện có

git worktree list

Kết quả hiển thị đường dẫn, commit và branch của từng worktree. Tùy chọn --porcelain tạo định dạng ổn định hơn nếu cần xử lý bằng script.

Tạo worktree cho một branch mới

Từ thư mục repository chính, chạy:

git worktree add -b feature/profile ../project-profile main
  • -b feature/profile tạo branch mới.
  • ../project-profile là thư mục của worktree mới.
  • main là điểm bắt đầu của branch.

Sau lệnh này, thư mục mới đã sẵn sàng để mở bằng IDE và commit bình thường.

Tạo worktree từ branch đã tồn tại

git fetch origin
git worktree add ../project-hotfix hotfix/payment

Nếu remote branch chưa có local branch, có thể tạo branch theo dõi:

git worktree add -b hotfix/payment \
    ../project-hotfix origin/hotfix/payment

Dùng detached worktree cho thử nghiệm

Khi chỉ muốn kiểm tra một commit hoặc chạy test mà không tạo branch, dùng --detach:

git worktree add --detach ../project-test HEAD~3

Thay đổi trong detached HEAD sẽ không thuộc branch nào cho đến khi bạn tạo branch hoặc cherry-pick commit sang nơi khác.

Một tình huống thực tế: xử lý hotfix khi đang làm tính năng

  1. Giữ nguyên thư mục hiện tại với toàn bộ thay đổi của feature.
  2. Tạo worktree hotfix từ branch production hoặc main.
  3. Cài dependency riêng nếu dự án sinh thư mục như vendor hoặc node_modules.
  4. Sửa lỗi, chạy test, commit và push trong worktree hotfix.
  5. Tạo pull request rồi quay lại thư mục feature; không cần pop stash.
  6. Sau khi merge, xóa worktree và branch hotfix nếu không còn dùng.
git fetch origin
git worktree add -b hotfix/login ../app-hotfix origin/main

cd ../app-hotfix
# sửa lỗi, kiểm thử
git add .
git commit -m "Fix login session handling"
git push -u origin hotfix/login

Xóa worktree đúng cách

Khi hoàn tất, quay về một worktree khác và dùng:

git worktree remove ../app-hotfix

Git sẽ từ chối xóa nếu worktree còn thay đổi chưa commit, trừ khi dùng --force. Hãy kiểm tra kỹ thay đổi trước khi cưỡng chế.

Sau khi xóa worktree, branch vẫn tồn tại và có thể xóa riêng nếu đã merge:

git branch -d hotfix/login

Dọn metadata khi thư mục bị xóa thủ công

Nếu thư mục worktree bị xóa ngoài Git, metadata có thể còn sót. Kiểm tra trước rồi dọn:

git worktree prune --dry-run
git worktree prune

Nếu worktree nằm trên ổ đĩa rời hoặc tạm thời không truy cập được, có thể khóa để Git không tự prune:

git worktree lock --reason "External drive" ../project-demo
git worktree unlock ../project-demo

Điều gì được dùng chung giữa các worktree?

  • Object database, commit, tag và phần lớn refs được dùng chung.
  • Mỗi worktree có HEAD, index và working directory riêng.
  • Một branch thông thường không thể được checkout đồng thời ở hai worktree.
  • Repository config mặc định được dùng chung; Git hỗ trợ worktree-specific config khi bật extensions.worktreeConfig.

Lưu ý với dependency và môi trường

Git dùng chung dữ liệu phiên bản, nhưng file không được track vẫn thuộc từng thư mục. Vì vậy mỗi worktree thường cần dependency và file cấu hình cục bộ riêng.

  • Không trỏ hai worktree vào cùng một node_modules nếu branch có dependency khác nhau.
  • Dùng port khác nhau khi chạy nhiều dev server đồng thời.
  • Tránh dùng chung database migration chưa tương thích giữa các branch.
  • Đặt tên thư mục theo mục đích: app-feature-cart, app-hotfix, app-review-123.
  • Không xóa worktree bằng file manager nếu có thể dùng git worktree remove.

Worktree hiệu quả nhất khi được xem như workspace có vòng đời rõ ràng: tạo cho một nhiệm vụ, hoàn thành, kiểm tra thay đổi rồi xóa đúng cách.

Khi nào nên dùng Git Worktree?

  • Xử lý hotfix mà không làm gián đoạn feature đang phát triển.
  • Review pull request trong một thư mục riêng.
  • So sánh hoặc chạy hai phiên bản ứng dụng cùng lúc.
  • Chạy tác vụ dài ở một branch trong khi tiếp tục làm việc ở branch khác.
  • Giữ một worktree ổn định để kiểm thử tích hợp.

Với công việc ngắn và working tree sạch, chuyển branch vẫn là lựa chọn đơn giản. Worktree phát huy giá trị khi việc chuyển ngữ cảnh thường xuyên bắt đầu làm gián đoạn dòng công việc.
